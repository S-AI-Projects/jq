# Spiral Matrix Maintenance and Test Generation

## Overview

The `spiral-matrix` exercise generates an $n \times n$ square matrix filled with natural numbers from $1$ to $n^2$ in inward, clockwise spiral order.

This document details the route from canonical problem specifications and track metadata to the generated Bats test file (`test-spiral-matrix.bats`), identifies hand-maintained versus auto-generated files, documents the exact reproduction command, and provides a case-to-output mapping with specific focus on the anchor test cases.

---

## Generation Route & Input Files

The generation route is mediated by the track generator (`bin/test-generator`), which compiles canonical data and exercise metadata into the target Bats test file using Jinja2 templating:

$$\text{canonical-data.json} + \text{tests.toml} + \text{config.json} \xrightarrow{\text{template.j2}} \text{test-spiral-matrix.bats}$$

### Input Files
1. **Canonical Test Specifications**:  
   `problem-specifications/exercises/spiral-matrix/canonical-data.json`  
   Cached by `configlet` in `$HOME/.cache/exercism/configlet/problem-specifications` (or `$HOME/Library/Caches/exercism/configlet/problem-specifications` on macOS). Defines the canonical test cases, inputs (`size`), expected matrices, and UUIDs.
2. **Track Test Inclusions & Metadata**:  
   `exercises/practice/spiral-matrix/.meta/tests.toml`  
   Controls which canonical UUIDs are included or excluded in the `jq` track.
3. **Exercise Configuration**:  
   `exercises/practice/spiral-matrix/.meta/config.json`  
   Defines solution (`spiral-matrix.jq`), test (`test-spiral-matrix.bats`), and reference implementation (`.meta/example.jq`) file paths.
4. **Jinja2 Test Template**:  
   `exercises/practice/spiral-matrix/.meta/template.j2`  
   Defines how Bats test blocks are constructed from canonical test cases, generating JSON heredocs for inputs and expected matrices.

## Reproduction Command

To reproduce test generation identically:

```bash
python3 bin/test-generator --no-pull exercises/practice/spiral-matrix
```

*Prerequisites:*
- Python 3 with `jinja2` installed.
- Canonical problem specifications cached via `bin/configlet info` or `bin/configlet sync`.
- On macOS systems where `configlet` caches under `~/Library/Caches`, ensure `XDG_CACHE_HOME="$HOME/Library/Caches"` or symlink `~/.cache/exercism/configlet/problem-specifications` to `~/Library/Caches/exercism/configlet/problem-specifications`.

Running the command produces a bit-for-bit identical test suite in `exercises/practice/spiral-matrix/test-spiral-matrix.bats`, with only the header timestamp comment (`# generated on <timestamp>`) reflecting the execution time.

### Anchor Cases Summary
- **Empty spiral (`size: 0`)**: Validates the zero-dimension edge case where an empty array `[]` is expected.
- **Trivial spiral (`size: 1`)**: Validates the base single-element matrix `[[1]]` without direction turns.
- **Spiral of size 2 (`size: 2`)**: Validates the minimal spiral requiring directional boundary turns (right $\to$ down $\to$ left).

## Reference Implementation Logic (`example.jq`)

```jq
def make_matrix($n):
  def fill($n; $elem): reduce range($n) as $i ([]; . + [$elem]) ;
  fill($n; fill($n; 0))
;

.size as $n
| {matrix: make_matrix($n), x: 0, y: 0, dx: 0, dy: 1, i: 1}
| until(.i > $n * $n;
    .matrix[.x][.y] = .i
    | if  .x + .dx < 0 or .x + .dx == $n or
          .y + .dy < 0 or .y + .dy == $n or
          .matrix[.x + .dx][.y + .dy] != 0
      then
        . + {dx: .dy, dy: -.dx}
      end
    | .x += .dx
    | .y += .dy
    | .i += 1
  )
| .matrix
```

Key aspects:
1. `make_matrix($n)`: Construct an $n \times n$ matrix initialized to zero using nested `reduce range($n)`.
2. Direction vector: Initialized to moving rightwards (`dx = 0, dy = 1`).
3. Clockwise rotation: `(dx, dy) = (dy, -dx)` applied when the candidate cell exceeds grid bounds ($< 0$ or $\ge n$) or already contains a non-zero value.
4. State iteration: `until(.i > $n * $n; ...)` increments `i` from 1 up to $n^2$.
